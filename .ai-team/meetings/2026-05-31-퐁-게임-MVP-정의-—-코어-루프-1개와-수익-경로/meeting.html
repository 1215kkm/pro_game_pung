강팀 회의 — 퐁 게임 MVP 정의 — 코어 루프 1개와 수익 경로

날짜: 2026-05-31 · 안건: 퐁 게임 MVP 정의 — 코어 루프 1개와 수익 경로 · 진행: 🎯 강팀장
🎯 강팀장

요청 재서술: 코드 0줄짜리 그린필드 레포 pro_game_pung. "퐁(Pong) 게임을 만든다"는 이름 외엔 정해진 게 없음. 오늘 회의 = 무엇을 만들지 한 가지로 못 박기.

반대 시각(스스로): "그냥 퐁 클론" 으로 시작하면 차별점·수익이 0. 클래식 퐁은 이미 수만 개. 한 회의 = 한 결정이니, "퐁의 어떤 변주를 코어 루프로 잡을지"까지 오늘 정한다.

안건

  1. 🧪 [UX] 코어 루프 — 첫 10초 안에 "한 판 더" 가 나오는 퐁 변주는? (조작·승패·리트라이 흐름)
  2. 🎨 [UI] 기술 베이스 + 화면 1장 — Canvas/HTML5 단일 페이지로 갈지, Crowny Class 토큰을 게임 UI에 어떻게 입힐지
  3. 💡 [수익] 심플 수익 경로 1줄 — 무료 웹게임에서 돈이 어디서 나오는가 (광고 리트라이 / 스킨 / 리더보드 시즌)
  4. 🛡️ [리스크] 웹게임 최소 리스크 — 점수 조작·개인정보 0수집 원칙·외부 의존성

참석: 강팀장 · 강디(UX+UI) · 강체크(품질+보안) · 아뱅(수익 아이디어). 강개발은 코드가 아직 없어 이번엔 산출물 없음 → 다음 회의 후 투입.

목표: 지속 사용 + 심플 수익. 한 회의 = 한 결정. 오늘의 결정 = "퐁 변주 1개 + 기술스택 + 수익 1줄".

🔥 아뱅

①표면 문제: "무료 웹 퐁, 돈 어디서 나?" → 반사적으로 "배너 광고 붙이자". 그게 통념이고, 그래서 망한다.

②숨은 진짜 문제: 광고는 지금 트래픽이 있어야 1원이라도 나온다. 코드 0줄짜리 MVP는 트래픽이 0이다. 광고는 수익이 아니라 유저가 떠나는 출구다 — 첫 10초 리트라이 루프(강디가 잡는 코어)에 배너가 끼면 "한 판 더"가 죽는다. MVP 단계에서 진짜 물어야 할 건 "돈"이 아니라 "무엇이 유저를 한 번 더 돌아오게 만드는가" = 리텐션 훅이다. 돈은 리텐션 위에만 박힌다.

③건드릴 심리 레버: 경쟁(사회적 증거) + 매몰비용. 점수는 공짜로 만들 수 있고, "내 최고기록"이 쌓이는 순간 떠나기 아까워진다.

④뒤집은 안 — "수익 모델"을 깔지 말고 수익이 자랄 토양(점수=공유=재방문) 하나만 깐다:

🔥 MVP 수익 1줄 추천: "죽는 순간 = 최고기록 갱신 + 1탭 공유 카드"를 코어 루프에 박는다. 결제·광고는 0줄로 시작. 이유 — 무료 웹게임의 수익은 결제버튼이 아니라 공짜 바이럴 트래픽에서 먼저 나온다(CAC↓). 광고(A)는 "다음 회의에서 DAU 500 넘으면" 켜는 스위치로 남겨둔다. 지금 켜면 빈 가게에 간판값만 낸다.

⑤수익 경로: 공유 카드 → 신규 유입 CAC 0원 → DAU 축적 → 그제서야 리워드 광고(A) 스위치 ON으로 직접수익 발생. 즉 오늘 박는 건 "수익 1줄"이 아니라 수익의 깔때기 입구다.

⑥선제 방어 + 시스템화: 점수 조작? MVP는 서버 검증 0 → 공유 카드에 "비공식 기록"이라 못 박고 리더보드는 다음 단계로(강체크 안건과 충돌 회피). 시스템화 = 공유율(공유/게임오버), 재방문율을 day1부터 기록 → DAU 500 도달 시 광고 A 자동 검토 트리거.

적용 원칙 #2(전제 의심: "무료=광고"를 깸) / 당긴 레버 경쟁+매몰비용+사회적증거 / 수익 경로 CAC↓(공유 바이럴) → 후행 광고수익

🎨 강디

현재 활성 디자인 스타일: #1 — Crowny Class (출처: styles/01-crowny-class.md)

다만 이건 게임입니다. 문서 §18 룰대로 주제에 맞는 테마를 먼저 제안합니다 — 게임·엔터: Primary #EF4444(레드) → Secondary #FACC15(옐로). 이유: 흥분·도파민·즉각 보상감. 그라데이션 각도 135deg·radius·shadow·spacing·폰트(Pretendard)·아이콘(Lucide)은 토큰 그대로 두고 브랜드 두 색만 갈아끼웁니다. (기본 보라/분홍으로 갈 거면 한마디만 주세요 — 즉시 롤백.)

① 사용자 목표

"잠깐 들어왔다가 10초 안에 한 판 끝나고, 손이 자동으로 '한 판 더'를 누른다." 게임 끝에서 사용자가 그만둘지 / 다시 할지를 즉시 고르게 한다. (아뱅이 잡은 매몰비용·최고기록 훅과 정합.)

② 흐름 (분기 ≤2 · 단계 ≤3)

추천 변주 = "원-패들 라이즈(One-Paddle Rise)". 클래식 2인 퐁은 상대(친구·AI)·매칭이 필요해 첫 10초가 안 나옵니다. 대신 벽 + 패들 하나 + 점점 빨라지는 공 — 모바일 한 손가락으로 패들을 좌우로 끌어 공을 계속 받아치고, 받아칠 때마다 +1점·공 가속. 놓치면 끝. 매칭·튜토리얼 0, 첫 터치 즉시 게임 시작. "한 판 더"가 구조적으로 강제됩니다(짧고·내 실력 탓·기록 갱신 욕구).

단계이탈 원인측정 지표
시작로딩 김·조작법 불명탭→첫 랠리 도달률, TTI<2s
받아치기조작 응답 둔함·너무 빨리 어려움평균 랠리 수·세션당 점수
게임오버"한 판 더" 약함·기록 자랑 욕구 없음재시작률(핵심)·세션당 판 수

조작 결론(모바일 우선): 터치=패들 좌우 드래그(공 따라 손가락), 마우스=커서 X추적, 키보드=←→. 한 입력 모델(가로 위치 1축)로 3기기 통일 → 강개발 분기 최소.

③ 시각 위계

게임 화면은 공·패들이 1순위(검은 캔버스 위 옐로 공·레드 패들이 가장 밝게 튐), HUD 점수 2순위(상단·흰색). 메뉴·게임오버 화면에서만 그라데이션 CTA("게임 시작"/"한 판 더")가 1순위 — 화면에서 가장 크고 빛나는 단 하나.

④ 기술 베이스 + 컴포넌트 + 상태

HTML5 Canvas 단일 페이지(SPA) 확정. 게임 보드는 <canvas> 60fps 렌더, 그 위/아래 메뉴·HUD·게임오버는 DOM 오버레이(Crowny 토큰 CSS 그대로). 즉 게임픽셀=Canvas, UI=토큰 DOM. 프레임워크 0(§19 순수 CSS).

⑥ 강개발 핸드오프

  • 화면 3장만: 메뉴 → 플레이(Canvas+HUD) → 게임오버 오버레이. 라우팅 없이 상태 전환(state: menu|playing|gameover).
  • 입력 1축 통일: 패들 X = clamp(터치/마우스/키보드). 3기기 같은 핸들러.
  • 최고기록 = localStorage (서버·개인정보 0 — 강체크 리스크 안건과 정합).
  • 토큰 파일 1개: §15 변수 + 게임 테마 오버라이드(레드/옐로)를 styles/tokens.css 한 파일에. Canvas는 JS에서 getComputedStyle로 같은 토큰 읽어 칠함 → 색 단일 출처.
  • gameover 진입 시 0.3s 페이드(--transition-slow), "한 판 더"는 즉시 포커스 가능.

🔍 강체크

① 검증 대상: 코드 0줄 기획 단계라 "동작 검증"은 불가. 대신 지금 박아두지 않으면 나중에 못 박는 두 가지 — (A) 안건4 웹게임 최소 리스크, (B) 안건1 코어루프가 "첫 10초 리트라이"를 실제로 보장하는지 엣지 관점. 23은 "코드 들어가기 전에 미리 박을 수용 기준"으로 적는다.

항목심각도악용/실패 시나리오우회안 (권장)
클라이언트 점수 → 리더보드 직신뢰🔴JS 콘솔/요청변조로 점수 9999999 제출. 시즌패스(수익)와 엮이면 보상 부정취득 → 정상 유저 이탈.MVP는 리더보드를 "로컬 베스트(localStorage)"로 한정 → 서버·수익 비연동. 글로벌 랭킹 도입 시점에만 서버 검증(시드 기반 리플레이 재현 or 입력 로그 검증) 추가. 즉, 치트 위험을 수익과 분리.
개인정보 0수집 원칙 가능성🟡닉네임 자유입력 = 실명/연락처/욕설 유입 가능. 광고 SDK는 동의 없이 기기ID·IP 수집 → 개인정보보호법·GDPR 동의 의무 발생 가능성.닉네임 = 선택·필명 가이드(실명 금지 안내)+금칙어 필터. 게임 로직 자체는 PII 0수집 유지. 광고/분석 SDK 도입 시 최초 진입 동의 배너+개인정보처리방침 1장 필수(위법 가능성 → 법무 검토 권고, 단정 X).
외부 의존성(광고SDK·Pretendard CDN·분석)🟡광고/CDN 차단(애드블록·망 차단)·다운 시 폰트 깨짐·게임 로딩 블로킹 가능. 분석 도구가 무동의 트래킹 시 규제 리스크.Pretendard는 self-host(폰트 번들 동봉)+system-ui 폴백으로 CDN 의존 제거. 광고 SDK는 비동기·실패시 게임 진행 보장(광고 안 떠도 플레이 가능). 분석은 무동의 시 익명·집계 전용 도구로 한정.
모바일 터치/회전/저사양 코어루프 깨짐🟡멀티터치 고스트 패들, 회전 시 공 이탈, 백그라운드 복귀 deltaTime 폭주 → "첫 10초 리트라이" 자체가 성립 안 됨.위 ② 엣지1~3을 구현 DoD에 포함. requestAnimationFrame + deltaTime 상한(clamp), 첫 터치만 추적, 회전 리사이즈 핸들러를 1차 구현 범위에 넣기.
리더보드 점수 입력 검증 부재🟢당장은 로컬이라 영향 적으나, 서버 전환 시 미검증이면 즉시 🔴로 승격.지금부터 점수에 이론적 상한·증가율 sanity check 클라이언트단 1차 방어 + 서버 도입 시 2차.

⑤ 사고 대응 한 줄: 리더보드 치트 발견 → ① 해당 점수 무효·시즌패스 보상 회수 ② 서버 검증 강제 전환 ③ 클라 점수 단독 신뢰 코드 폐기. (지금 "로컬 한정"으로 가면 이 사고 자체가 발생 불가 — 그게 우회안의 핵심.)

⑥ 배포 권고: 코어루프 1개 + 로컬 베스트 리더보드 + self-host 폰트 + 광고 실패시 진행 보장까지면 MVP로 안전. 서버 글로벌 랭킹·시즌패스를 코어루프와 동시에 붙이는 것은 치명 리스크(🔴)라 보류 권고 — 광고/스킨 수익부터, 랭킹 수익은 검증 설계 후.

🎯 강팀장 마감 요약 — 텔레그램으로도 발송됨

강팀장은 회의 마감 시 아래 SUMMARY 블록을 *반드시* 채운다. 이 안의 내용이 텔레그램 메시지 본문으로 그대로 전송된다.

결정

  • 코어 루프 → 퐁 변주 = "원-패들 라이즈(One-Paddle Rise)". 벽+패들 1개+가속하는 공, 한 손가락 1축 조작, 놓치면 즉시 게임오버 → "한 판 더". 매칭·튜토리얼 0.
  • 기술 베이스 → HTML5 Canvas 단일 페이지(SPA), 프레임워크 0. 게임=Canvas 60fps, UI(메뉴·HUD·게임오버)=Crowny 토큰 DOM 오버레이. 화면 3장(menu/playing/gameover).
  • 디자인 테마 → Crowny Class 토큰 유지 + 게임·엔터 브랜드 2색만 교체(레드#EF4444 / 옐로#FACC15). 토큰은 styles/tokens.css 단일 출처, Canvas도 getComputedStyle로 같은 토큰 사용.
  • 수익 1줄 → MVP는 결제·광고 0줄. "게임오버 = 최고기록 + 1탭 공유 카드"로 CAC 0원 바이럴을 깔때기 입구로 깐다. 리워드 광고("이어하기")는 DAU 500 도달 시 켜는 스위치로 후행.
  • 리스크 차단 → 최고기록은 localStorage 로컬 베스트만(서버 랭킹·개인정보 0). Pretendard self-host, 광고 실패해도 게임 진행 보장.

미결정 / 다음 회의 안건

  • 서버 글로벌 리더보드 + 시즌패스 → 강체크 🔴(클라 점수 직신뢰 시 치트가 수익과 결합). DAU·바이럴 지표 확보 후 "서버 점수검증" 설계와 함께 별도 회의.
  • 게임 테마 색 → 레드/옐로로 갈지, 기본 보라/분홍 유지할지 CEO 한마디로 확정(강디는 즉시 롤백 가능).
