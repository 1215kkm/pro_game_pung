날짜: 2026-05-31 · 안건: 게임 소개 허브 사이트 — 그리드 + 애드센스 수익 · 진행: 🎯 강팀장
🎯 강팀장

요청 재서술: 여러 게임을 모아 보여주는 허브(소개) 사이트. 그리드 한 페이지, 칸마다 썸네일, PC에선 마우스 호버 시 간략 설명, 모바일 2~3열. 그리드 중간중간 구글 애드센스로 수익. 게임은 앞으로 계속 추가 예정.

반대 시각(스스로): "그리드 + 애드센스 박기"는 쉬운데, 애드센스는 승인·정책이 까다롭고(빈약한 콘텐츠·클릭유도 거부), 광고를 그리드에 막 끼우면 CLS(레이아웃 밀림)로 게임 카드 오클릭 → 계정 정지 위험. "어떻게 박느냐"가 핵심.

안건

  1. 🎨 [UI/UX] 그리드 한 페이지 설계 — 카드(썸네일+제목), PC 호버 설명 vs 모바일(호버 없음) 대체, 반응형 열 수(모바일 2~3 / PC 다열), 게임 추가가 쉬운 데이터 구조(JSON 한 곳 수정)
  2. 💡 [수익] 애드센스 배치 전략 — 그리드 사이 어디에 몇 개가 수익↑이면서 정책·UX 안전한가, 승인 받기 위한 최소 조건, 광고 vs 사용성 균형
  3. 🛡️ [리스크/품질] 애드센스 정책·기술 리스크 — 오클릭/무효클릭, CLS, 동의(개인정보·GDPR)·ads.txt, 콘텐츠 정책, 접근성·성능

참석: 강팀장 · 강디(UI/UX) · 아뱅(수익·애드센스 전략) · 강체크(정책·리스크). 강개발은 결정 후 구현.

목표: 한 회의 = 한 결정. 오늘 = "그리드 구조 + 애드센스 배치 규칙 + 게임 추가 방식" 확정.

🔥 아뱅

① 표면 문제: "그리드에 애드센스 끼워서 돈 벌자."

② 숨은 진짜 문제: 지금 애드센스를 논하는 것 자체가 함정이다. 트래픽이 0인데 광고 배치를 고민하는 건 손님 0명인 가게의 진열대 간격을 재는 꼴. 게다가 게임 1개짜리 그리드는 애드센스 승인이 거의 안 난다 — 구글 정책상 "최소한의 콘텐츠 / 가치 없는 페이지"로 자동 거부된다. 진짜 문제는 "광고를 어디 박나"가 아니라 "승인 받을 콘텐츠 두께"와 "광고 띄울 사람"을 먼저 만드는 것이다.

③ 건드릴 심리 레버: 호기심 갭(Curiosity Gap) — "이 게임 못 깨면 바보" 류의 도전 카피로 클릭 유발 / 보조로 사회적 증거(플레이 횟수 카운터). 광고 자체엔 레버를 못 건다(정책상 광고 클릭 유도 금지) → 레버는 전부 게임 카드와 유입 카피에 건다.

④ 뒤집은 안

안 A — 승인 전엔 애드센스를 아예 빼라. 게임 1개로 신청하면 거부 이력이 남아 재신청이 더 까다로워진다. 승인 현실 조건(2026 기준): 독자 콘텐츠 페이지 다수, 명확한 내비게이션, 개인정보처리방침·소개·문의 페이지 필수, 그리고 사실상 일 방문 30~50 이상의 자연 트래픽. → 게임 카드마다 "공략/설명 본문 200자+"를 붙여 게임당 1개의 콘텐츠 페이지로 만들면, 게임 4~5개만 모여도 "소개+공략 글 5개 + 정책 페이지 3개" = 승인 가능한 두께가 된다. 그리드는 메뉴, 진짜 콘텐츠는 게임별 상세.

안 B — 승인 전 기간을 "트래픽 자산화"에 쓴다(돈은 나중, 사람은 지금). 광고가 0원이어도 이메일/푸시 구독과 SNS 클립은 쌓인다. "튕기기" 신기록 영상 15초 클립 → 쇼츠/릴스. 카피 A/B는 아래 표.

안 C — 승인 후엔 "광고 밀도"가 아니라 "광고 1개당 RPM"으로 본다. in-feed 광고는 칸수가 아니라 스크롤 깊이로 넣는다. 표 참고.

⑤ 수익 경로: (1) 승인 전 — 수익 0이 정상, 대신 구독자·트래픽이라는 "미래 RPM의 곱셈 계수"를 쌓음. (2) 승인 후 — 일 100명 × in-feed RPM ₩1,500~3,000(한국 게임 카테고리 가정) ≈ 일 ₩150~300, 월 ₩5~9만으로 시작 → 트래픽이 곱이므로 일 1,000명이면 월 50~90만. 핵심: 수익은 트래픽의 종속변수. (3) 보조 수익 한 줄: 게임 추가될수록 "게임 제작자/스폰서 입점"(고정 카드 노출 광고)이 애드센스보다 RPM 10배 — 트래픽 생기면 직접 판매로 전환.

⑥ 선제 방어 + 시스템화: 우선순위 = ① 정책 페이지 3종 + 게임별 상세(콘텐츠 두께) → ② 트래픽 30~50/일 → ③ 애드센스 신청 → ④ in-feed 6~9칸 규칙으로 배치. 광고 배치는 맨 마지막. 시스템화: 게임 JSON에 adSlotEvery: 8 한 필드로 밀도 제어, 광고 카드는 항상 "Sponsored" 라벨+다른 스타일, 첫 광고 위치 고정 → 사람이 매번 안 만지게.

⑥ 배포 권고: 🔴 두 건(오클릭·CLS / 빈약 콘텐츠)은 코드·콘텐츠 단계에서 반드시 차단해야 할 게이트다. 특히 "광고를 그리드 칸 안에 섞기"는 금지 — 광고는 독립 행 + 높이 예약으로만. 승인은 게임 10개+ 와 정책/방침 페이지 확보 전에는 신청하지 말 것. 🟡 4건(CMP·PIPA 방침·ads.txt·라벨)은 런칭 전 체크리스트로 묶어 처리. 강개발 구현 시 위 우회안을 사양으로 박고, 게임 추가 때마다 "오클릭·CLS" 회귀 1케이스 재실행 권고. 발견 사항은 .ai-team/last-qa-findings.txt에 적재.

3. 게임 진입클릭했는데 로딩만 돌고 안 뜸 / 잘못 눌러 광고로 감카드→플레이 전환율, 오클릭률(아뱅·강체크 게이트)

강체크 🔴 게이트 수용: 광고는 카드와 같은 행에 절대 안 섞음 → 그리드 흐름 안에 "전용 광고 행" 으로만 삽입. 카드 식별성을 위해 광고 카드는 radius·배경·"광고" 라벨로 게임 카드와 시각 분리.

③ 시각 위계 — 허브는 CTA가 "카드 자체"다. 첫째: 썸네일 이미지(칸의 70% 차지, 가장 먼저 눈에 옴) → 둘째: 제목(--font-xl 20px / weight 700, 썸네일 위 또는 아래) → 셋째: 설명·태그(--font-sm 16px / muted). 호버 시에만 보라→분홍 그라데이션 테두리(--gradient)로 "지금 이거 누르면 들어간다"를 강조. 광고 행은 일부러 위계 아래로 — 게임 카드보다 튀면 안 됨.

④ 카드 컴포넌트 + 상태

상태표현
기본흰 카드(--light-card), 보더 --light-border, radius 16px(--radius-xl), --shadow-md. 썸네일 16:9, 그 아래 제목+1줄 설명+태그칩.
hover (PC만)translateY(-2px) + --shadow-lg + 2px 그라데이션 보더. 설명이 1줄→3줄로 펼쳐짐(높이 예약). 모바일은 hover 없음.
focus(키보드)box-shadow: 0 0 0 3px rgba(138,56,245,0.30) (접근성 §14). 카드는 <a>로 Tab 진입.
loading(스켈레톤)썸네일·제목 자리에 --light-hover 회색 박스 + shimmer. 실제 카드와 같은 높이 → CLS 0(강체크 케이스 통과).
empty게임 0개일 때: 중앙에 Lucide gamepad-2 + "곧 새 게임이 추가됩니다 🎮" + muted 텍스트. 빈 그리드 방치 X.
error(썸네일 깨짐)이미지 로드 실패 시 그라데이션 배경 + 제목 첫 글자 이니셜 타일로 폴백. 회색 깨진 아이콘 절대 노출 X.
광고 칸전용 행 1개(카드 옆에 안 붙음), min-height 예약(모바일 280px), 배경 --light-hover + 점선 보더로 게임 카드와 구분, 상단에 16px "광고" 라벨(--text-muted). 아뱅 권장형 = 6~9카드마다 1행 + 첫 광고는 2스크롤 아래부터.

구현은 grid-template-columns: repeat(auto-fill, minmax(160px, 1fr)) 기반 + 위 분기로 미세 조정. 모바일 카드도 터치 타겟 44px 이상.

모바일 호버 대체 (요청 핵심) — 모바일엔 hover가 없으니 설명 1줄을 카드에 항상 노출한다(제목 아래 --text-muted 16px, 1줄 말줄임 ellipsis). 탭하면 바로 게임 진입(설명 펼치기용 추가 탭 X — 마찰 제거). PC는 평소엔 1줄, hover 시 3줄로 펼침. 즉 모바일=항상 1줄 / PC=호버로 3줄 한 컴포넌트의 두 모드.

그리드 와이어프레임 (PC 5열, 광고 전용 행)

⑥ 강개발 핸드오프 — 픽셀 아니라 토큰·동작·데이터로 넘김.

  • 그리드 = display:grid; gap:var(--spacing-lg) + 위 반응형 열 수(미디어쿼리 4개). 카드는 <a href="{url}">로 통째 클릭+키보드 포커스.
  • 썸네일 aspect-ratio:16/9 + object-fit:cover + loading="lazy"(LCP·트래픽 절감). 깨지면 onError로 이니셜 타일 폴백.
  • 설명: 모바일 1줄 -webkit-line-clamp:1, PC hover 시 :hover로 3줄. 높이 예약해 hover로 레이아웃 안 밀게.
  • 광고 = 게임 카드와 다른 컴포넌트. 그리드 안에 grid-column:1/-1 풀폭 행으로만 삽입. min-height 예약. 데이터에서 adSlotEvery(아뱅 제안)로 N카드마다 자동 끼움.
  • 상태 5종(default/hover/focus/loading/empty/error) + 광고행 전부 CSS로. loading 스켈레톤은 실제 카드 치수 동일.

게임 추가용 데이터 스키마 — games.js 또는 games.json 한 곳에 객체 추가만 하면 카드 자동 증가:

// games.json — 게임 하나 = 객체 하나. 이 배열에 추가만 하면 그리드에 카드가 늘어남.
{
  "adSlotEvery": 8,          // 8카드마다 광고 전용 행 1개 (아뱅 권장 6~9)
  "games": [
    {
      "id": "bounce",                 // 고유 식별자(영문, url-safe)
      "title": "튕기기",               // 카드 제목 (--font-xl)
      "desc": "공을 튕겨 최고 점수에 도전!",  // 1줄 설명 (모바일 항상 노출 / PC 호버 3줄)
      "thumb": "images/bounce.jpg",   // 16:9 썸네일 경로 (없으면 이니셜 폴백)
      "url": "play.html?game=bounce", // 클릭 시 이동할 플레이 화면
      "tags": ["아케이드", "1인"],      // 태그 칩 (0~3개 권장)
      "new": true                      // (선택) "NEW" 배지 표시 여부
    }
  ]
}

필드 정리 — 필수: id·title·desc·thumb·url. 선택: tags(배열)·new(불리언). 첫 게임 "튕기기"는 이미 play.html이 있으니 url만 맞추면 그대로 들어감. CEO가 게임 추가할 땐 이 객체 하나 복사→값만 교체가 전부.

체크리스트 ✓ 흐름 먼저(3단계·분기2) · 임의 HEX 0(활성 토큰만) · 폰트 전부 ≥16px · 상태 6종+광고행 명시 · 모바일 호버 대체 확정(항상 1줄) · PC/모바일 토큰 동일(레이아웃만 분기) · 광고는 전용 행으로 흐름 안 깸 · 데이터 스키마 제공.

🎯 강팀장 마감 요약 — 텔레그램으로도 발송됨

강팀장은 회의 마감 시 아래 SUMMARY 블록을 *반드시* 채운다. 이 안의 내용이 텔레그램 메시지 본문으로 그대로 전송된다.

결정

  • 그리드 구조 → 한 페이지 반응형 그리드. 열 수 모바일 2 / 태블릿 3 / 랩탑 4 / 데스크탑 5. 카드 = 썸네일 + 제목.
  • 호버 설명 → PC는 마우스 호버 시 설명(최대 3줄), 모바일은 호버가 없으니 카드에 항상 보이는 1줄 설명으로 대체.
  • 게임 추가 방식 → games.json 에 객체 1개 복붙(id/title/desc/thumb/url/tags)만으로 카드 자동 추가. 코드 수정 0.
  • 애드센스 배치 규칙(핵심) → 광고는 게임 카드와 같은 행에 섞지 않고 풀폭 "전용 행"으로만 삽입. 6~9카드마다 1개, 첫 광고는 2스크롤 아래. 컨테이너 min-height 예약(CLS 0) + "Sponsored" 라벨 + 카드와 다른 색/radius.
  • 애드센스 도입 시점 → 지금은 넣지 않는다. 트래픽 0 + 게임 1개로 신청하면 "빈약 콘텐츠"로 거부되고 이력이 남는다. 먼저 게임 수 + 게임별 상세/정책 페이지 + 자연 트래픽을 만든 뒤 신청.
